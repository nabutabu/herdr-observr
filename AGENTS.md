# AGENTS.md — herdr-observr

Guidance for any AI coding agent (or human) working here. Read before changing
anything — it encodes decisions already argued out and verified against a live
Herdr instance; re-litigating them wastes time and invites regressions.

## What this is

`herdr-observr` is a Go plugin for [Herdr](https://github.com/nabutabu/herdr)
(a terminal multiplexer / agent-management tool). It subscribes to Herdr's live
event stream and exports agent runtime *health* telemetry — where agents are
stuck, how long they wait for a human, how much concurrent work is happening —
over OTLP.

**Privacy (non-negotiable):** never transmit *what* an agent is doing — no pane
content, terminal output, or transcripts. Only lifecycle/state metadata (ids,
states, timestamps) leaves the process. Reject or flag any change that risks
putting pane/terminal content on the wire.

## Wire-protocol facts (constraints — confirmed live against Herdr v0.9.0)

1. **No respawn on startup-hook crash.** Herdr restarts a crashed `[[startup]]`
   process only on the next boot, and `plugin.log.list` keeps a single entry.
   `app.subscribeWithBackoff`'s initial-connection path caps out at 5 attempts /
   ~31s; past that the process exits and telemetry is dead for the boot. An
   external-process supervisor (open item 1.2) is the fix.
2. **One connection, one purpose.** A subscription connection cannot also serve
   RPCs (and plain RPCs don't share either). One long-lived connection for the
   subscription (owned by a dedicated reader goroutine); every RPC opens its own
   short-lived connection via `client.Call`. Never mix the two.
3. **Pushed events carry no sequence/revision.** `pane.agent_status_changed` on
   the wire is `{agent, agent_status, pane_id, workspace_id}` (+ occasional
   nesting — see `event.go`'s `eventPayload`/`workspaceRef`/`paneRef`). Idempotent
   tracker `Apply*` upserts are the only dedup mechanism.
4. **No top-level `type` field on the wire frame** — events arrive as
   `{"event": ..., "data": {...}}`. `parseFrame`/`wireFrame` is the single-pass
   classify+normalize; do not reintroduce a classify-then-normalize split (was a
   real double-unmarshal bug).
5. **`done` can't be pushed via RPC.** `pane.report_agent` accepts
   `idle|working|blocked|unknown` only. But reporting `idle` on an
   unfocused/unseen pane lets Herdr's detection convert `idle && !seen` → `done`.
   Leaving `done` fires the event-driven close path (`ApplyAgentStatusChanged`),
   verified sub-second accurate; the seen-flip close path only fires from the
   real TUI focused on the pane (headless CLI can't flip `seen` — unit fixtures
   still construct `done` synthetically, which is fine).
6. **Subscriptions can die silently** — no socket error, just silence, after
   repeated subscribe/disconnect cycles. `Tracker.Run`'s periodic
   `session.snapshot` diff is the primary defense, not a backstop.
7. **No cross-machine id exists in Herdr.** Pane env vars are only
   `HERDR_ENV/PANE_ID/TAB_ID/WORKSPACE_ID/SOCKET_PATH/BIN_PATH`; Herdr's own ids
   are server-scoped. `herdr.machine.id` is a UUID generated by the plugin and
   persisted under `HERDR_PLUGIN_STATE_DIR` (`internal/machineid.LoadOrCreate`);
   hostname is a display-only secondary attribute.
8. **`session.snapshot` has `tabs[]` and `layouts[]`** beyond
   workspaces/panes/agents. `layouts[]` is UI geometry — deliberately unmodeled.
   Tab events (`tab.created/closed/renamed`) are subscribed and wired. Closing a
   tab emits **no `pane.closed`** for its panes — `ApplyTabClosed` cascades them.
   A last-tab `tab.closed` is followed by `workspace.closed`; the double cascade
   is idempotent.
9. **Status-change events are structurally pane-scoped.** Herdr rejects an
   unscoped subscribe, so a pane created after the last subscribe is invisible
   until the subscription is rebuilt. `internal/app/scope.go` +
   `paneCreatedNeedsResubscribe` trigger an immediate resubscribe on a new
   uncovered pane instead of waiting for the next reconcile tick.
10. **`agent_session` is "frontmost right now", not a stable pane↔session
    binding** — it flips between sessions across polls. Key usage/cost
    attribution by session id, never by pane; `Tracker.Diff` excludes
    `AgentSession` to avoid spurious drift.

## Architecture

```
main.go                 entrypoint; signal handling → internal/app
internal/app/
  app.go                lifecycle: ping → bootstrap snapshot → subscribe → event loop →
                        reconnect-on-error → reconcile/pane-gap resubscribe → evict ticker
  scope.go              subscribed-pane set for status events; replaced on every (re)subscribe
  telemetry.go          OTel meter/logger/tracer instruments + nil-safe record* methods
  app_test.go           scope + resubscribe-trigger + event-routing tests
internal/client/        client.go: Dial/Call/SocketPath; rpc.go: NDJSON Request/Response framing
internal/events/        subscription.go: kind consts + SubscribeFromSnapshot;
                        subscriber.go: dedicated conn + reader goroutine (Events()/Err());
                        event.go: Kind enum, NormalizedEvent, parseFrame (single-pass) — incl. tab kinds
internal/snapshot/      snapshot.go: Response/Snapshot/Workspace/Pane/Tab structs, Fetch()
internal/otel/          resource.go (BuildResource: env resource + machine id/hostname),
                        meter.go (OTLP MeterProvider + instrument constructors),
                        log.go (state-change events), trace.go (short state-change spans)
internal/tracker/       tracker.go: mutex-guarded maps + sessions attribution index; per-kind Apply*
                        writers; ApplySnapshot re-baseline; Diff/DiffReport; Run (reconcile);
                        EvictExpired (grace window); counts.go: per-state Counts()
internal/machineid/     machineid.go: LoadOrCreate persisted UUID (fact #7)
internal/usage/         collector.go + adapter.go: event-driven active-pane set; usage deltas
                        keyed by session id; adapters/opencode: reads opencode.db read-only
internal/version/       version.go: release version
herdr-plugin.toml       plugin manifest: [[build]] → scripts/build.sh, [[startup]] → ./bin/herdr-observr
scripts/build.sh        local Go toolchain, falls back to latest prebuilt release binary
deploy/                 local demo stack (compose.yaml): collector, Prometheus, Loki, Tempo, Grafana
```

Ownership rules — preserve when extending:

- **`Subscriber`** exposes no write surface after construction; RPCs always go
  through `client.Call` on fresh connections.
- **`Tracker.mu` is the real single-writer guarantee**, not "only the event loop
  calls `Apply*`." Almost every write does come from `app.Run`'s loop, but
  `Tracker.Run`'s reconcile goroutine calls `ApplySeenFlip` directly — safe
  (mutex-serialized, a correct no-op if a real event raced it). New tracker
  writers must be event-loop-routed or provably `mu`-safe; don't assume the
  mutex is redundant.
- **`app.reconnect` is the only path that rebuilds the subscription** — hard
  error, reconcile drift, or uncovered pane all funnel through the same
  `resubscribe` channel and the same re-bootstrap (fresh snapshot →
  `ApplySnapshot` → `SubscribeFromSnapshot` → replace `a.scope`). `reconnect`
  and `scope` are event-loop-only; they touch `a.sub`/`a.scope`, not `Tracker`.
- **`internal/usage`** receives everything via non-blocking channel handoffs
  (`NotifyTransition`/`RequestSync`); only its own `Run` goroutine touches
  collector state — that indirection is what makes `reconnect`'s `RequestSync`
  safe while `Run` is live.

## Conventions

- **Constructed types over package-level globals** (`Tracker`, `Subscriber`,
  `App`, `scope`): state in explicitly constructed, injected structs — keeps
  everything independently testable.
- **No double-decode.** One `json.Unmarshal` pass in `parseFrame`; splitting
  classify/normalize was tried and reverted.
- **Idempotent state application, not sequence-based dedup** — no sequence
  numbers on the wire (fact #3). `Apply*` always upserts by id; never assume
  ordering.
- **Reconciliation is primary, not a backstop.** It is the sole detector of a
  silently stalled subscription, including tab-membership drift. Only
  pane-coverage gaps run faster (`scope`/`paneCreatedNeedsResubscribe`, fact #9).
- **Spike before building** anything that touches the live socket; batch findings
  into one coherent plan change instead of editing the plan incrementally.
- **Built ≠ running** — a package isn't done until something in
  `internal/app`/`main.go` actually calls it.

## Testing

```sh
go test ./...
```

Wire-protocol tests use stub Unix-socket servers (`net.Listen("unix", ...)` in a
temp dir — see `startStubServer` in `internal/client/client_test.go`,
`internal/events/subscriber_test.go`), not higher-level mocks; framing bugs only
show up at that layer. Tracker and usage tests bypass the wire entirely —
feeding `NormalizedEvent` values to `Apply*` methods, and fixture adapters to
the collector. Live-instance verification happens separately via throwaway spike
binaries against `HERDR_SOCKET_PATH`, not in `go test`.

## Environment

- Go 1.26+
- `HERDR_SOCKET_PATH` — required; path to Herdr's Unix socket
- `HERDR_PLUGIN_STATE_DIR` — where the persisted `herdr.machine.id` UUID lives
  (fact #7); in standalone runs set it yourself or the attribute is omitted with
  a warning
- `OTEL_EXPORTER_OTLP_ENDPOINT` — OTLP/gRPC collector endpoint (SDK default).
  Unreachable is not a startup failure: gRPC exporters dial lazily, exports are
  dropped instead of failing startup
- `OTEL_SERVICE_NAME` — defaults to `herdr-telemetry`
- `OTEL_RESOURCE_ATTRIBUTES` — extra comma-separated resource attributes
- `XDG_DATA_HOME` — where the opencode usage adapter finds `opencode.db`;
  falls back to `$HOME/.local/share/opencode/opencode.db`
